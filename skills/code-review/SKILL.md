---
name: 代码审查
description: 对指定文件或改动做结构化代码审查
tags: developer, review
---
目标：对用户指定的文件、目录或 diff 做一次结构化代码审查。

1. 若未指定范围，先用 `git_status` / `git_diff` 查看当前改动；改动为空时询问要审查哪些文件。
2. 用 `read_file` 逐个读取相关文件；大文件用 `search_text` 定位关键函数后再精读。
3. 按以下维度检查并记录问题：
   - 正确性：边界条件、空值、错误处理、并发安全
   - 可读性：命名、函数长度、重复代码
   - 性能：明显的重复计算、无谓拷贝、N+1 查询
   - 安全：注入、路径穿越、密钥硬编码、越权
   - 一致性：是否与项目既有风格和抽象层次一致
4. 每条问题给出：文件:行号、问题描述、影响、修改建议（必要时给出代码片段）。
5. 按严重程度排序（阻断 / 重要 / 建议），不要罗列无关紧要的格式问题。
6. 最后给出总体判断：可以合入 / 修改后合入 / 需要重做。

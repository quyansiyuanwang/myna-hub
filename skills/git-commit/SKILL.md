---
name: 规范化提交
description: 根据当前改动生成并创建规范化提交
tags: developer, git
---
目标：根据当前工作区改动生成一条规范化提交并创建它。

1. 调用 `git_status` 查看改动范围，调用 `git_diff` 阅读具体改动。
2. 若改动为空，直接告诉用户没有可提交的内容。
3. 归纳改动的**意图**而不是逐条罗列文件，判断类型：feat / fix / refactor / perf / style / docs / test / chore。
4. 生成提交信息：
   - 首行：`type(scope): 摘要`，不超过 72 字符，使用祈使语气
   - 需要时在正文补充「为什么」与影响面，每行不超过 100 字符
5. 把生成的提交信息给用户确认后再调用 `git_commit`；用户要求直接提交时跳过确认。
6. 提交后调用 `git_log` 确认结果，并简述本次提交内容。
